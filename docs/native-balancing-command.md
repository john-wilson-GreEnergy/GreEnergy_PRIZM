# Native balancing command validation

The deployed EMS `turtle.war` includes a protobuf `SetStringBalancingConfiguration` command (payload field 30). Its default `BatteryPackBalancingConfiguration` has `chargeDeadband` at field 5 and `dischargeDeadband` at field 6. The legacy `/tools/controls/ems/.../balance/avg` and `/balance/provided/...` handlers do not accept those values; query parameters were silently ignored, and BMS readback showed 0/0 instead of the requested 10/50 mV.

PRIZM now builds the native protobuf in `src/server/balancingCommandProto.ts`. Active balancing sends it to the EMS binary command endpoint only when `PRIZM_BALANCING_PROTO_ENABLED=true`. With the flag absent or false, active balancing fails closed before any ADB or rotation preparation. Stop balancing retains its existing Turtle URL. The old URL helper now rejects active balancing so it cannot falsely claim to apply deadbands.

Offline checks: `npx tsx src/server/balancingCommandProto.test.ts` and `npx tsx src/server/balancingControlService.test.ts`. These establish the protobuf field encoding and legacy-path guard, but do not establish live EMS acceptance or BMS application.

Before enabling at a site, perform a supervised one-string test with ADB/rotation preflight, record the requested deadbands and command ID, verify EMS acceptance, then independently confirm every BPC's mode and deadbands in fresh readback and persistence after at least one ADB cycle. If acceptance or readback fails, leave the flag disabled and investigate; do not interpret HTTP acceptance or active shunts alone as proof of the requested settings. Do not test an entire array before one-string parity has been demonstrated.

## Per-string asynchronous verification

Active commands now return EMS acceptance and a verification job ID separately from application success. The server performs read-only retries for up to 180 seconds per accepted string. Each string that matches is checked again at least 65 seconds later, with 30 seconds of readback recovery allowance. All jobs share a four-request read limit. Matched strings are not polled again until their persistence check is due. Equipment commands are never automatically resent.

Freshness requires both the string and every BPC timestamp to be post-command, no older than 30 seconds, and not more than five seconds in the future. Complete unique BPC coverage must match the existing canonical inventory; missing inventory is unavailable, not success. An explicit provided target and both deadbands must match exactly. For average balancing only, resolved `BALANCE_TO_PROVIDED` targets may straddle adjacent integer-mV values (a 1 mV spread observed during rolling EMS updates). Larger spreads remain unresolved; plausible range remains 2500–3800 mV. Resolved settings are consistent with the request, not proof of its provenance or active shunting.

The String List keeps a persistent, expandable per-string result panel and resumes the same job ID after page reload in the same browser tab. Jobs are in memory; server restart/expiry is explicitly unverified. Partial acceptance still closes the send dialog and tracks accepted strings. A never-matched string is `mismatch`, not `changed`; `changed` requires a prior verified match. No shunts is not a settings failure. Stop-balancing delivery and activity verification are unchanged.

Read-only validation on 2026-09-23 found Array 7 / String 26 eventually reporting 5/10 mV on all 14 BPCs without a resend; the canonical fleet subsequently reported 320/320 matching deadbands. Earlier readings were off/0/0. The exact cause of that delayed application has not been established. Do not bypass device permissions or interlocks to resolve an unverified result.

Tests: `npx tsx src/server/balancingVerification.test.ts`, `npx tsx src/server/balancingControlService.test.ts`, `npx tsx src/lib/balancingVerificationClient.test.ts`, and `npx tsx src/components/BalancingVerificationPanel.test.tsx`. These use fixtures, not live control writes. Rollback: set `PRIZM_BALANCING_PROTO_ENABLED=false` to fail closed for active balancing, or revert this verification commit and rebuild. Turning off the flag does not stop balancing already applied to hardware.
