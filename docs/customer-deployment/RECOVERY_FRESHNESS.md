## Design before implementation

- Publish a small, immutable contactor-only snapshot on completion of the existing successful primary last-call acquisition. No new poll, timer, device request, command, or retry.
- Reuse one per-string contactor normalizer in both the bulk snapshot and early publication. Preserve source time, explicit identity and polarity; never stamp device observations with arrival/publication time.
- Bind the acquisition to profile/station/block/EMS identity captured before the request, and reject completion after an identity change. Reject fallback, failed, malformed and out-of-order acquisitions. A failed current acquisition clears early availability; no silent fallback to older full-snapshot feedback.
- Use the early snapshot only for supervised recovery context/observation. General workspace telemetry, alarms and command-dispatch authorization remain on their existing paths. No incomplete alarm list is exposed to the UI.
- Keep recovery's per-target 15-second freshness check and unresolved-target exclusion unchanged. Slow upstream data can still fail freshness; this is not a guarantee of continuous fresh telemetry.
- Rollback with `PRIZM_RECOVERY_EARLY_TELEMETRY=false`, selecting the existing full-snapshot recovery source while retaining authentication, receipts and freshness checks. Early snapshot is memory-only and starts unavailable after restart.
- Correct the REST provider's timeout lifetime: it currently stops the timer after headers, leaving body transfer unbounded. Keep its deadline active through body consumption and always clear it in `finally`. This does not increase the configured deadline or permit stale feedback.

## Next-cycle freshness correction — design

Recent live cycles 45–48 still serialize StringViewer detail enrichment (roughly 0.8–1.2 seconds) behind EMS acquisition, postponing the next primary read. Move only the existing scheduled StringViewer batch off the full-snapshot critical path. A single background owner must bound concurrency and retain the existing batch budget/TTL policy; do not introduce another timer or duplicate acquisition loop. Normalization merges available cache entries with their original source time, age and stale provenance. Missing entries remain unavailable until a subsequent publication. ## Shared primary reader — design before implementation

Introduce an opt-in `PRIZM_PRIMARY_EMS_READER=true` hybrid path. A single owner replaces (never supplements) the coordinator's lastCall request. It uses the existing REST provider, exact enrolled-profile endpoint, GET only and no local-mock fallback. Other reports remain coordinator-owned. The reader publishes the compact recovery projection immediately and retains one parsed result; each full cycle receives a detached copy, so later background completions cannot mutate an in-progress snapshot. Acquisition sequence numbers are independent of full coordinator cycle numbers and must be labeled as such in diagnostics.

Bound load to one request in flight, at least four seconds between starts and at least one second between completion and the next start; failures back off to 8/16/30 seconds. Coordinator reads renew a 60-second demand lease; lack of demand stops scheduling. A profile/endpoint change discards old results and drains the old request before starting another, even across sites. Stop cancels scheduling; drain waits for the current provider deadline. Missing/failed/wrong-site results never inherit prior recovery eligibility. Original per-string timestamps and the 15-second safety limit remain unchanged. Flag off restores the existing coordinator reader on process restart.

Validate deterministic ownership, timing/backoff, scope changes, failure invalidation, detached result parity and stop/drain with mocks; run type checking/build and local live comparison before any remote deployment. The live comparison must report source age on arrival separately from publication age and request duration; a faster cadence cannot repair already-old source telemetry. This experiment is not a compliance or physical-state verification claim.

With the shared reader enabled, schedule ordinary full-cycle preparation at four seconds rather than two, so shorter preparation does not automatically double optional endpoint traffic. Existing explicit refresh and Feather coalescing remain. Startup stops/restarts the coordinator; the owner therefore supports start after stop, invalidating the old generation while still draining it before another request. A rollback-mode local restart exposed this lifecycle requirement before the new reader was activated.

## Passive response-stage measurements — design

Instrument the existing coordinator-owned lastCall read only; do not increase its rate or activate the experimental reader. The REST provider may emit optional timing metadata after completion/failure: time awaiting response headers, body read/decoding time, provider total, status, and the parsed HTTP Date timestamp. The caller measures JSON parsing, payload byte count, request-window process CPU usage and local event-loop delay. Retain at most 30 metadata-only records in the existing coordinator debug response. `PRIZM_EMS_STAGE_TIMING=false` disables collection; no data payload, credentials, URLs or headers are copied to the diagnostic record.

Header wait includes connection/queueing, transport and EMS work; it is not a direct measurement of EMS generation time. Body duration includes transfer, decoding and local scheduling; process CPU and event-loop delay include other PRIZM work in the same window. HTTP Date is coarse and does not prove synchronized clocks. Report these limitations and correlate stages with unchanged per-string source age and existing coordinator phases. Observers must never change acquisition results or deadlines, and timeout/failure paths must release monitors. Validate with mocked transport and compare live behavior after a local restart; keep the Dell and controller settings unchanged.
